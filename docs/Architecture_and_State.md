# Sublink Worker 工作原理与状态管理文档

本文档旨在解释 Sublink Worker 的核心工作原理、链接转换流程以及其状态管理机制。

## 1. 核心工作原理：链接转换流程

Sublink Worker 的核心功能是将各种格式的代理节点信息转换为不同客户端（如 Sing-box, Clash, Surge, Xray）所需的配置文件。这个过程可以概括为 **"输入 -> 中间表示 (IR) -> 输出"**。

### 1.1 输入解析 (Input Parsing)

系统首先接收用户提供的输入，这通常是一个包含代理节点信息的字符串。输入处理逻辑主要在 `src/BaseConfigBuilder.js` 中实现。

系统支持两种主要的输入形式：

1.  **结构化配置 (YAML/JSON)**:
    *   系统尝试将输入解析为 YAML 或 JSON 对象。
    *   **关键点**：目前系统**仅**查找 `proxies` 字段（这是 Clash 配置的标准字段）。
    *   如果找到 `proxies` 数组，系统会提取其中的每个节点对象。
    *   **局限性**：由于 Sing-box 使用 `outbounds` 字段存储节点，且结构不同，目前的解析器无法直接识别 Sing-box 的完整配置文件。

2.  **行链接列表 (Line-by-Line Links)**:
    *   如果结构化解析失败，系统会将输入按行分割。
    *   每一行被视为一个独立的代理链接（如 `vmess://...`, `ss://...`）或一个订阅链接（`http://...`）。
    *   对于订阅链接，系统会发起网络请求获取内容，然后递归地进行解析。

### 1.2 中间表示 (Intermediate Representation - IR)

为了支持多种输入和输出格式，系统引入了一个标准化的**中间表示 (IR)** 层。

*   **作用**：IR 是一个通用的节点对象结构，它抽象了不同协议（VMess, Shadowsocks, Trojan 等）的共同特征。
*   **流程**：无论输入是 Clash 的 YAML 节点还是 `vmess://` 链接，解析器（位于 `src/parsers/`）都会将其转换为统一的 IR 对象。
*   **优势**：这使得系统只需要编写 "Input -> IR" 和 "IR -> Output" 的转换逻辑，而不需要为每一对 "Input -> Output" 编写转换代码（例如，不需要专门写 "Clash -> Sing-box" 的转换）。

### 1.3 配置生成 (Config Generation)

最后一步是将 IR 节点列表转换为用户请求的目标格式。

*   **构建器**：针对每种目标客户端，都有一个专门的构建器（如 `SingboxConfigBuilder`, `ClashConfigBuilder`）。
*   **转换**：构建器接收 IR 节点列表，将其映射为目标客户端特定的配置结构（例如，将 IR 节点转换为 Sing-box 的 `outbounds` 对象）。
*   **规则与策略**：构建器还会根据用户的选择（如“按国家分组”、“启用去广告规则”等）生成相应的路由规则和策略组。

## 2. 服务状态管理 (State Management)

关于“服务是否是有状态的”，答案是：**部分有状态，但核心转换逻辑是无状态的。**

### 2.1 无状态部分 (Stateless)

*   **核心转换逻辑**：链接转换本身是完全无状态的。
    *   给定相同的输入字符串（代理链接）和参数（如目标客户端类型），系统总是即时计算并返回相同的结果。
    *   系统不会在服务器端“记住”你上次转换了什么链接，除非你使用了短链接功能。
    *   所有的配置信息（节点列表、规则选择等）都包含在生成的长链接 URL 参数中（`config` 参数）。

### 2.2 有状态部分 (Stateful)

系统利用 Cloudflare KV (Key-Value) 存储来实现一些有状态的功能：

1.  **短链接 (Short Links)**:
    *   当生成的订阅链接太长时，用户可以点击“生成短链接”。
    *   **状态存储**：系统会将长链接的完整参数（包括节点信息）存储在 KV 中，并生成一个短码（如 `/s/abc12345`）。
    *   **状态依赖**：短链接的访问依赖于 KV 中存储的数据。如果 KV 数据丢失或过期，短链接将失效。

2.  **自定义基础配置 (Custom Base Config)**:
    *   用户可以上传自定义的基础配置模板（例如，自定义的 DNS 设置或路由规则）。
    *   **状态存储**：这些自定义模板的内容被存储在 KV 中，并分配一个 ID。
    *   **引用**：生成的订阅链接会通过 `configId` 参数引用这些存储在 KV 中的配置。

3.  **远程订阅缓存 (Remote Subscription Caching)**:
    *   虽然文档中未详细展开，但通常这类 Worker 会对远程订阅的内容进行短时间的缓存，以减少对源站的请求压力。这也可以被视为一种临时的状态。

### 总结

*   如果您只是使用“转换”功能并直接使用生成的长链接，服务表现为**无状态**。
*   如果您使用了“短链接”或“保存配置”功能，服务表现为**有状态**，依赖于后端的 KV 存储。
